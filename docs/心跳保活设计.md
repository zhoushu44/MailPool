# 心跳保活功能

> ✅ 已实现。定时对邮箱池内账号执行"拟真操作"，保持账号活跃，防止微软风控判定为僵尸号。
> 参考：inbox-warmer（heartbeat cron tick）、email-warmup-stack（8周 ramp 排期）、OutlookManager（IMAP 连接池）。

---

## 一、目标

微软对长期不登录、不交互的账号会逐步降低信任分，最终可能：
- 限制 IMAP/Graph 访问
- 要求重新验证
- 直接封禁

心跳保活通过**定时静默操作**让账号保持活跃信号：
- Graph API 拉取收件箱（模拟"打开邮箱看信"）
- 可选：给自己发测试邮件（模拟"正常使用"）
- 可选：标记邮件已读（模拟"阅读交互"）

---

## 二、两种保活模式

### 模式 A：静默拉取（默认，零风险）

```
操作：Graph API GET /me/messages?$top=5
频率：每天 1 次（随机时间点）
风险：极低（只读操作，不发送/不修改）
效果：让微软看到"这个账号每天有正常登录和收件箱访问"
```

### 模式 B：拟真交互（可选，更接近真人）

```
操作：
  1. Graph API 拉取收件箱（GET /me/messages?$top=5）
  2. 标记 1-2 封未读邮件为已读（PATCH /me/messages/{id}）
  3. 可选：给自己发 1 封短文本邮件（POST /me/sendMail）

频率：每天 1 次
风险：低（正常使用行为，非群发）
效果：完整模拟真人"看信+阅读+偶尔发信"
```

> 默认用模式 A；模式 B 需用户手动开启（设置页开关）。

## 三、调度设计

### 定时任务（APScheduler / 系统定时）

```python
# 伪代码
async def heartbeat_job(db: Session):
    """每日心跳保活：对池内 healthy 账号执行静默拉取。"""
    # 1. 查出所有 healthy 状态的 outlook 账号
    accounts = db.query(EmailAccount).filter(
        EmailAccount.provider == "outlook",
        EmailAccount.status == "healthy",
    ).all()

    # 2. 串行处理（不并发）
    for acc in accounts:
        try:
            cred = json.loads(acc.account_json)
            token = _request_access_token(
                cred["refresh_token"], cred["client_id"], GRAPH_SCOPE
            )

            # 更新 refresh_token（微软可能轮换）
            if token.get("refresh_token"):
                cred["refresh_token"] = token["refresh_token"]
                acc.account_json = json.dumps(cred)

            # Graph API 拉取收件箱
            access_token = token["access_token"]
            req = urllib.request.Request(
                f"{GRAPH_BASE}/me/messages?$top=5&$select=id,subject,isRead",
                headers={"Authorization": f"Bearer {access_token}"},
            )
            resp = urllib.request.urlopen(req, timeout=15)
            messages = json.loads(resp.read()).get("value", [])

            # 模式B：标记已读
            if warmup_mode == "interactive" and messages:
                unread = [m for m in messages if not m.get("isRead")]
                if unread:
                    msg_id = unread[0]["id"]
                    patch_req = urllib.request.Request(
                        f"{GRAPH_BASE}/me/messages/{msg_id}",
                        data=json.dumps({"isRead": True}).encode(),
                        method="PATCH",
                        headers={
                            "Authorization": f"Bearer {access_token}",
                            "Content-Type": "application/json",
                        },
                    )
                    urllib.request.urlopen(patch_req, timeout=10)

            # 更新保活时间
            acc.last_check_at = _now()
            db.commit()

            print(f"  ✓ {acc.email} 保活成功")

        except Exception as e:
            err = str(e)[:100]
            print(f"  ✗ {acc.email} 保活失败: {err}")
            # 连续失败 → 标记 unhealthy
            # （需要失败计数器，简化版直接标记）

        # 随机间隔 5-15 秒（避免规律性请求）
        time.sleep(random.uniform(5, 15))
```

### 调度参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| 执行时间 | 每天 09:00（本地时区） | 可配置 |
| 模式 | `silent`（静默拉取） | `silent` / `interactive` |
| 每号间隔 | 5-15 秒随机 | 防规律性 |
| 连续失败阈值 | 3 次 | 连续失败 N 次标记 unhealthy |
| 跳过条件 | status != healthy | 只保活已验证的号 |

### 调度方式（三选一）

**方案 1：APScheduler（推荐，随服务启动）**
```python
# main.py 启动时注册
from apscheduler.schedulers.asyncio import AsyncIOScheduler
scheduler = AsyncIOScheduler()
scheduler.add_job(heartbeat_job, "cron", hour=9, minute=0, args=[db])
scheduler.start()
```

**方案 2：系统定时任务（Windows 计划任务 / Linux cron）**
```bash
# 每天早上 9 点执行
0 9 * * * cd /path/to/MailPool && python -m app.tools.heartbeat
```

**方案 3：API 触发（手动保活）**
```
POST /api/admin/pool/heartbeat
→ 立即执行一次保活（用于测试/手动触发）
```

## 八、失败处理

| 场景 | 处理 |
|---|---|
| token 过期（invalid_grant） | `fail_count += 1`，达到阈值降级 |
| 账号被风控（403） | `fail_count += 1`，达到阈值降级 |
| 网络超时 | `fail_count += 1`，跳过本次（下次再试） |
| 连续失败 3 次 | 自动降级 `unhealthy`（暂停保活与取号） |
| 连续失败 6 次 | 自动降级 `dead`（彻底剔除） |
| 保活成功 | `fail_count = 0`，保持 `healthy` |

> 降级机制与[健康扫描设计文档](健康扫描设计.md)共用同一套 `fail_count` 阈值（3 → unhealthy，6 → dead），由 `_apply_check_result()` 统一处理。

## 十、风控防护

```
1. 串行不并发（每号间隔 5-15s 随机）
2. 只读操作为主（silent 模式零风险）
3. 每天最多 1 次（不过频）
4. 执行时间随机抖动 ±30 分钟（09:00 → 实际 08:30-09:30 随机）
5. 连续失败自动暂停该账号（标记 unhealthy）
6. 不发送群发邮件（interactive 模式只给自己发）
7. 不在非工作时间执行（避免凌晨异常请求触发风控）
```
